# vm-sync V0.2.0 审计文档：influx-sync 实测部署教训移植（2026-08-16）

> 背景：influx-sync 真机隔离装置部署（docs/deployment-hxjh-2026-08-16.md）暴露 6 个
> 部署级缺陷（V1.7.4~V1.8.0）。本批把其中适用于 vm-sync 的缺陷逐条移植修复，
> 供双 AI 互审（AGENT.md §6：审阅方请独立复验下列每项的证据与测试）。

## 移植清单与结论

| # | influx-sync 原型缺陷 | vm-sync 是否命中 | 修复 |
|---|---|---|---|
| VM1 | `backfill: all` 被误入通用 duration 校验表（`bad duration "all"`），专门处理 all/0 的代码成死代码 | ✅ 命中（config.go 同款代码） | 移出校验表 + 补负值拒绝 + 回归测试 |
| VM2 | N15：查询响应 512MB **静默截断**（半截 JSON 落库丢尾部） | ✅ 命中（ExportRange 512MB 无 +1 检测） | +1 探测显式报错（提示调低 max_window）+ 回归测试 |
| VM3 | N14：窗口只在"完全空窗"翻倍，稀疏库回填被基础窗口封顶（实测 16 天级） | ✅ 命中（emptyStreak 仅空窗计数） | 欠满翻倍：空/稀疏窗均计数，真空区上限 1h、稀疏区封顶 MaxWindow（响应有界）+ 回归测试 |
| VM4 | N16：查询与处理串行（源库查询 ~1.8s/轮 是瓶颈），发送端等米下锅 | ✅ 命中（export → 分块 → 编码串行） | 单窗口轮次查询预取流水线 + window_target 解耦 + 回归测试 |
| VM5 | N15 配套：查询失败后窗口增长不复位 → 大窗口持续失败停滞 | ✅ 命中 | export 失败复位增长计数，下轮基础窗口自愈 + 回归测试 |
| VM6 | （e2e 测试设施）假目标单次 `Body.Read` 截断 >4KB 帧，静默丢尾部行 | ✅ 命中（旧帧 ≤3.4KB 从未暴露，VM3 大窗口后帧变大暴露） | 假目标改 `io.ReadAll`（仅测试修复，产品代码无此问题） |

**不适用项**：N12（SHOW SHARD GROUPS 列索引——VM 用 export 二分探测，无此查询）、
ParallelQueries<=1 强制 4（vm poller 单 export 无并行分段）、
loadgen 挂死（vm-sync 无 bench 工具）、拆批重复编码（VM 行瘦，帧按行/字节双阈值分块）。

## 修复要点（供审阅）

### VM1+VM5 补充：负值拒绝
influx-sync V1.7.4 的修复只移出了校验表；vm-sync 同时补了负值拒绝
（influx-sync 同款在 V1.7.4 已加）。`backfill: "-5d"` 现在显式报错。

### VM3 细节：双档窗口上限
- 全空 streak（真空区）：翻倍上限 **1h**（响应为空，安全）；
- 出现过稀疏窗后：翻倍上限 **MaxWindow**（30s 默认）——导出响应内存有界。
  注：vm-sync 无 influx-sync 的"翻倍窗口按 MaxWindow 切片"机制（单次 export 一把梭），
  故稀疏窗用 MaxWindow 封顶换取内存安全；稀疏→突发稠密的 1h 真空退出场景由
  VM2 的显式超限报错 + VM5 失败复位自愈（报错→基础窗口重试），不依赖切片。

### VM4 细节：预取消费语义
- 消费轮**直接采用预取槽的窗口边界**（streak 每轮变化，重算必然失配——这是
  influx-sync N16 测试暴露后修正的设计）；
- 仅当槽游标 ≠ 当前游标（上一轮失败未推进）才丢弃同步重查——零丢失兜底；
- 预取启动放在欠满判定**之后**（窗口估算用刚观测到的密度，增长不滞后一轮）；
- 水位截断在预取启动时同样适用。

## 遗留（审阅方注意）

1. vm-sync-fork（/home/wjl/vm-sync-fork，feature/isolation-sync）内嵌的 app/vm-sync
   平铺副本尚未同步本批修复——计划随后移植并更新 FORK.md；
2. 稀疏区 MaxWindow 封顶（VM3）比 influx-sync 的 1h 切片保守：稀疏库回填速率
   ≈ MaxWindow/查询延迟；如需更快可移植切片机制（或调大 max_window，代价=导出
   响应内存随窗口增大）；
3. vm-sync 无快路径（VM 本体无订阅推送），实时性=轮询（watermark 1s，e2e
   ≈1.5~2.5s），与 influx-sync 快路径 <1s 的差距属已知 V2 计划（vmagent 双写）。
